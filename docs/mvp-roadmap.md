# LIVIBE MVP 路線圖

## 產品定位

LIVIBE 是面向大眾的演唱會資訊與體驗評價平台，優先服務 K-pop、J-pop 與華語市場，也保留擴展至各國藝人的能力。平台的核心價值是：讓使用者找到海內外演出、理解場次資訊，並以透明、可追溯的方式分享演後體驗。長期目標是成為演唱會領域具指標性的評價資料庫，建立在真實場次、足夠樣本與清楚計算規則之上。

## 第一版（MVP）

### 已交付／應交付功能

- **演出探索**：首頁可瀏覽演出卡片，依藝人、類型、城市或關鍵字尋找演出。
- **即將舉行／歷史演出**：清楚區分尚未舉行、已完成與取消／延期（若資料已知）的場次；歷史場次可進入演後評價。
- **期待度與演後評價分流**：未演出場次只收集「期待度」；演出結束後才顯示並收集實際體驗評價，兩者不混算。
- **樣本數**：每個分數旁標示評分人數；樣本不足時顯示「樣本不足」，不作為排行榜指標。
- **評分透明**：第一版採 1–10 的整體分數，頁面說明平均值計算方式與目前樣本數；多維度評分留待正式會員版加入。
- **本機原型儲存**：原型階段可在瀏覽器本機保存使用者的收藏、期待度或草稿評價，方便驗證互動流程。
- **場館視野**：演出頁提供場館基本資訊與座位／視野參考；若為示意資料，需明確標示為示意，不能視為保證視野。
- **可分享座位定位**：場館、舞台配置與座位區會同步到網址參數，使用者可直接分享相同視野位置。
- **穩定演出識別**：資料重建時為每個演出產生包含首日與場館的穩定 ID，並保留舊網址與本機評價的相容讀取。
- **功能預告**：以「規劃中」或「即將推出」標示帳號、通知、認證入場、社群與票務等尚未提供的功能，不讓使用者誤以為已可使用。

### 原型限制

本版是可展示與驗證流程的前端原型，限制如下：

- 無正式後端、共用資料庫或即時同步；本機資料不會成為公共評價。
- 無跨裝置帳號與登入；換瀏覽器或裝置可能無法保留本機資料。
- 無真實票務交易、付款、轉讓、退款或官方票券驗證。
- 無公開實名或身分認證；目前不能宣稱評論者已入場或為真實姓名使用者。
- 演出、場館與評論資料若非明確標示來源，不應視為完整或即時的官方資料。

## 第二階段：帳號、後端與可信評價

- 建立正式 API、資料庫與基本帳號系統。
- 建立「藝人 → 巡演 → 城市站 → 日期場次」資料模型。
- 支援每帳號每場次一次評分、修改紀錄與基本防灌分機制。
- 以票券、訂單或其他可接受憑證設計「認證入場」標籤；不公開真實姓名。
- 提供評論檢舉、管理、刪除原因與評分計算版本紀錄。

## 第三階段：跨國資料、通知與社群聚合

- 擴充繁中、英文、日文、韓文等介面與藝人多語別名搜尋。
- 支援國家、城市、時區、幣別、場館與官方售票來源資料。
- 提供開賣、加場、延期、取消及關注藝人的通知。
- 聚合社群討論時保留來源、原文連結與授權／退出機制，避免無來源搬運。
- 增加評論回覆、按讚／有幫助、標籤、劇透標示與座位視野照片。

## 第四階段：票務媒合

- 先提供官方售票連結、開賣提醒與候補需求登記。
- 再評估使用者求票／讓票意願媒合，並加入帳號信譽、檢舉與防詐機制。
- 只有在法規、付款、退款、個資與爭議處理流程明確後，才評估站內交易；不把票務交易視為 MVP 承諾。

## MVP 驗收條件

- 使用者能從首頁找到演出，並清楚辨識即將舉行與歷史場次。
- 未演出場次只能提交或查看期待度；已完成場次才能進入演後評價流程。
- 所有展示分數均同時顯示樣本數；樣本不足時不呈現為具代表性的排名結果。
- 評分頁能看到計算說明、樣本數與資料狀態，且不製造不存在的認證或即時資料。
- 收藏、期待度與評價草稿在同一瀏覽器重新整理後仍可讀取，並清楚標示為本機原型資料。
- 場館視野內容可被定位至對應場館或明確標示示意，不宣稱座位體驗保證。
- 尚未實作的帳號、認證、通知、社群聚合與票務功能均有清楚的功能預告或限制說明。
- 以桌機與手機瀏覽器完成基本瀏覽、場次切換、評價流程與錯誤狀態檢查；不得因未來功能尚未完成而阻塞 MVP 核心流程。
